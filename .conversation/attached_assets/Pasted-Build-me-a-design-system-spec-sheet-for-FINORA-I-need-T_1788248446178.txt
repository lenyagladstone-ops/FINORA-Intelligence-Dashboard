Here's my brain dump: Build a web app with three screens: Onboarding, Main Dashboard, and Judge Panel. Full flow below.

## Screen 1 — Onboarding (Personal Info + Vision Board)

Multi-step form, one question group per step, progress indicator at top.

*Step A — Personal info*
- Name, age band, monthly investable surplus (range, not exact figure)
- Investing experience: none / beginner / intermediate / advanced
- Current holdings (optional): equity, mutual funds, F&O, none
- Risk tolerance mini-quiz: 3–4 scenario questions ("market drops 15% overnight, what do you do?") used to seed the Investor DNA agent

*Step B — Vision board*
- Visual card grid of goals: House, Retirement, Child's education, Startup capital, Travel, Emergency fund, Wealth growth
- User taps to select one or more, then drags to rank priority
- Each selected goal asks for a rough target amount and timeframe (dropdown ranges, not free text)
- This output feeds the Goal Planner agent directly

*On submit:* compute an initial suggested persona (one of the 5 below) from the risk quiz + vision board, but let the user override it — don't lock them in.

## Screen 2 — Main Dashboard

Layout, top to bottom:
1. *Market ticker strip* — scrolling live/simulated prices for a watchlist, color-coded up/down
2. *Signal feed* — cards for current market events, each tagged with a classification label (momentum / volume anomaly / sentiment) and a confidence percentage
3. *Persona selector* — 5 cards in a row (Novice/Foundation, Growth & Accumulation, Aggressive/Speculative, Advanced/Sophisticated, Preservation & Legacy), the user's suggested persona pre-highlighted, others selectable
4. *Portfolio/watchlist widget* — current holdings or watchlist state, simple table or card list

*Interaction:* tapping any signal card while a persona is selected opens the Judge Panel for that event, scoped to that persona.

## Screen 3 — Judge Panel (the core feature)

Full-screen or large modal, styled like a courtroom/panel view. Structure top to bottom:

*Header:* the market event being discussed + which persona's "lens" is active, with a small control to switch persona and re-run the panel live (this is what proves differentiated output on identical input — make switching feel instant).

*Persona weight strip:* a compact horizontal bar per agent showing how much that persona amplifies or mutes it (High/Med/Low). This makes the persona's influence visible before reading any opinion.

*Agent opinion cards — one per agent, each with a stance, a short written rationale, a confidence score, and ONE pictorial element specific to what that agent does:*

| Agent | Stance shown | Pictorial element |
|---|---|---|
| Memory Agent | similar-to-history read | small line chart overlaying today's move on the closest historical analog |
| Devil's Advocate | top counter-risks | horizontal bar chart ranking 2–3 risks by severity |
| Truth Verification | verified / unverified | source-confidence badge + a short cited snippet from the filing, with a link to the source document |
| Ripple Effect | sector spillover | radial/spoke diagram showing 3–4 affected sectors and impact strength |
| Behavioral Psychology | bias flag | semi-circle gauge from calm to FOMO/panic |
| Goal Planner | fit with stated goal | progress bar showing how this event moves the user toward or away from their vision-board goal |
| Investor DNA | personality read | small radar chart (risk appetite, patience, diversification, conviction) |
| Guardian Angel | proceed / caution / stop | traffic-light indicator with a one-line reason if not green |

*Synthesis footer:* one final synthesized recommendation, built by combining the 8 agent stances weighted by the active persona, with an overall confidence score and the citation(s) it relied on. Show it as a distinct card, visually separated from the individual agent opinions above, so the reasoning chain (individual views → weighted merge → verdict) stays visible rather than collapsing into a single black-box answer.

*Degraded-data state:* if a data feed or filing is unavailable, that agent's card shows "data unavailable" instead of a stance, and the synthesis footer flags the recommendation as partial rather than silently proceeding.
