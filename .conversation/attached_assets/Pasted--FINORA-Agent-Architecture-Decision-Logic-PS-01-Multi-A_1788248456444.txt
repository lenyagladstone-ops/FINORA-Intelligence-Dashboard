# FINORA — Agent Architecture & Decision Logic
### PS-01: Multi-Agent Autonomous Financial Intelligence System for Retail Investors

## 1. Overview

FINORA turns a market signal into a personalized, cited, and explainable recommendation
by running eight specialized agents in parallel over the same event, then merging their
opinions through a persona-specific weighting scheme. The same input event produces a
different verdict for each of five investor personas — that difference is the core proof
point of the system, and it is visible live in the Judge Panel screen.

## 2. Data flow

```
Market data / filings (simulated feed)
        │
        ▼
Signal Classification  →  momentum | volume anomaly | sentiment  (+ confidence)
        │
        ▼
8 agents run in parallel, each consuming: the signal + the active persona's
weight profile + the user's onboarding profile (risk score, goals)
        │
        ▼
Synthesis layer: weighted merge of 8 agent polarities → recommendation + confidence
        │
        ▼
Judge Panel UI: individual opinions → weighted merge → verdict (reasoning chain stays visible)
        │
        ▼
Performance log: persona used, latency, confidence, forward-return proxy
```

## 3. The eight agents

Each agent has a fixed structured-output contract (a stance, a confidence score, and a
`polarity` in the range −1..+1 that feeds the synthesis layer) so the synthesis code never
depends on any one agent's internal representation.

- **Memory Agent** — matches the current move against the closest historical analog and
  reports a pattern-match percentage; polarity comes from the direction the analog
  ultimately moved.
- **Devil's Advocate** — pulls 2–3 counter-risks from a risk library keyed to the signal's
  classification, ranks them by severity; polarity is negative and scales with average
  severity.
- **Truth Verification** — the RAG-grounded agent. It checks the signal against a
  (simulated) filing corpus, returns verified/unverified with a cited source and a short
  excerpt. If the underlying filing is unavailable, it returns `unavailable` instead of
  guessing — this is the degraded-data path.
- **Ripple Effect** — maps the event's ticker to 3–4 related sectors and estimates spillover
  strength and direction for each, rendered as a spoke diagram.
- **Behavioral Psychology** — scores the crowd's likely emotional state from calm to
  FOMO/panic based on the signal type, nudged by the active persona (aggressive personas
  read the same event as more exciting; conservative ones read it as more alarming).
- **Goal Planner** — measures whether this event moves the user's #1 vision-board goal
  closer or further away, using the goal captured at onboarding.
- **Investor DNA** — a four-axis personality read (risk appetite, patience, diversification,
  conviction) seeded from the active persona's base profile.
- **Guardian Angel** — the safety agent. It combines Devil's Advocate severity, Truth
  Verification status, and the Behavioral score into a single proceed/caution/stop
  call, adjusted by how much leniency the active persona is given.

## 4. Persona weighting

Each of the five personas (Novice/Foundation, Growth & Accumulation, Aggressive/
Speculative, Advanced/Sophisticated, Preservation & Legacy) carries a High/Med/Low weight
per agent — e.g. Novice weights Guardian Angel and Devil's Advocate High and Ripple Effect
Low, while Aggressive does the reverse. Switching personas in the Judge Panel re-weights
and re-renders all eight cards instantly (pure client-side recompute, no reload), which is
what proves "different outputs for different profiles on identical input."

## 5. Synthesis algorithm

`weighted polarity = Σ(agent polarity × persona weight) / Σ(persona weight)`, with any
agent that returned `unavailable` excluded from the confidence average. Thresholds map the
result to **Accumulate** (>0.15), **Hold & Watch** (−0.15 to 0.15), or **Reduce / Avoid**
(<−0.15). Overall confidence is the weight-adjusted mean of the contributing agents'
individual confidence scores.

## 6. Degraded-data handling

The HDFC/Adani-style "unavailable filing" scenario is handled explicitly: Truth
Verification returns `unavailable` rather than fabricating a citation, Guardian Angel
treats that as a risk factor, and the synthesis footer is labeled **"Partial
recommendation"** rather than silently presenting a full-confidence verdict.

## 7. Personalization source

The onboarding flow (personal info + risk mini-quiz + ranked vision-board goals) produces
a risk score and a top goal, which seed a suggested starting persona — the user can always
override it. This is the "user profiling component that modifies agent outputs" required
by the brief.

## 8. Performance log

Every time a signal is opened or a persona is switched inside the Judge Panel, a log row
is captured: persona used, synthesized recommendation, confidence, a simulated agent
response latency (ms), and a simulated 30-day forward-return proxy — the three measurable
per-session metrics the brief asks for.
